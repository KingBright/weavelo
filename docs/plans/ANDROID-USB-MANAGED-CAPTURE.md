# Android USB 托管投屏

状态：具体方案待确认；尚未实现。2026-10-31。

## 目标与边界

两台 Mac 分别通过已授权 USB ADB 管理实际连接的手机。电脑按需启动采集，其他 Weavelo 设备可自动观看，无需每次操作手机的 MediaProjection 确认框。手机脱离托管电脑时继续使用现有、由 Android 授权的独立投屏方式。

这是一条使用既有 ADB 调试授权的采集路径，不给 APK 自动授予 MediaProjection，不修改系统安全策略、无障碍开关或设备签名。首次 ADB 配对及已撤销授权的重新配对仍由本人完成。

当前对象：Book 的努比亚 NX741J（324662166861），Studio 的红米 14C / 2409BRN2CC（UGXC8DQGDYBATKB6）。只按精确序列号选择设备，不按连接顺序选择。

## 最小实现

1. 在连接手机的电脑上增加 USB 来源管理器，只管理当前可用、已授权的 ADB 设备；没有观看者时停止采集。
2. 通过 ADB 启动临时手机端采集代理，使用系统允许 shell 调试主体调用的屏幕采集及 MediaCodec 硬件编码能力。先完成视频，控制和音频分别接入与验收。
3. 电脑接收 H.264/H.265 压缩帧，直接接入现有 Weavelo 鉴权会话和媒体传输；观看端沿用原生解码、呈现。禁止为转发增加一次解码、CPU 像素转换和重新编码。
4. 来源明确显示“努比亚（USB · 经 Book）”或“红米（USB · 经 Studio）”。它属于托管电脑的附属来源，不冒充手机 APK 的设备身份，不复制或重建手机配对凭据。与 APK 设备条目的合并不作为第一步前提。
5. 协议仅增加当前 USB 来源描述及必要的编码来源能力；所有自有客户端统一更新，不保留旧协议兼容分支。现有网络隔离、来源修订及输入绑定保持。

## 共享逻辑与生命周期

- 复用会话、权限、来源目录、几何转换、输入所有权及网络传输；手机端保留平台采集、硬件编码和系统输入适配器。
- 统一传递可见矩形、编码尺寸、旋转、色彩信息、时间戳和编码器配置。保留来源给出的色彩元数据，不猜测矩阵或以假 FPS 代替真实画面。
- 输入使用常驻代理及现有绑定机制，不为每个鼠标事件启动一次 adb 进程。实际控制能力取决于该手机已具备的调试输入权限，不自动修改系统设置。
- USB 拔出、代理退出、手机重启或几何变化立即取消手势并废止旧来源绑定。重新插入只恢复同一序列号对应的来源；不能将旧控制转给另一台手机。
- 代理通信限定在所选 ADB 连接及会话内，限制帧和控制消息大小；身份由当前托管电脑的已鉴权 Weavelo 会话提供。实现前按实际本地通信接口做聚焦审查。
- 手机锁定、受保护画面及厂商限制按实际系统能力呈现；不提供自动解锁或保护内容绕过。

## 完成条件

先在 NX741J 证明不弹 MediaProjection 对话框的实际视频采集，再覆盖红米及四台电脑观看。分别记录硬件编码器、实际呈现、延迟、CPU/GPU、USB/网络码率和持续运行结果；不以解码提交充当物理呈现。

控制必须在专用窗口或应用内验证点按、拖动、中文及 emoji、旋转、DPI 和输入法挤压后的坐标，以及拔线时的释放。音频单独验证实际输出。未完成的项目明确保留，不以视频成功代替控制、音频成功。

沿用 main 单工作区、现有正式打包和兼容升级流程；不新增分支、人工补丁哈希审批、发布代际或回退副本。

## 依据

- [Android MediaProjection](https://developer.android.com/media/grow/media-projection)：普通应用的每个新投屏会话需要用户确认。
- [Android ADB](https://developer.android.com/tools/adb)：调试连接必须经过设备本人的授权。
- [scrcpy 官方项目](https://github.com/Genymobile/scrcpy)：已授权 USB/TCP 调试连接可承担设备采集与控制，作为平台实现可行性参考；这不是 Weavelo 已完成验收的证明。
