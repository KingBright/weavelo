# 跨设备复制粘贴与跨远程窗口拖拽

2026-11-06，按用户需求持续实现；主分支、单工作区，复用当前鉴权和文件传输，不新增旧协议兼容分支。

## 目标与边界

文本、图片、文件复制后，可以像本机一样在当前远程窗口粘贴；随后支持把内容从一个远程窗口直接拖到另一个远程窗口。保留应用的系统拖放语义，不把“上传到下载目录”称为已完成目标应用的原生放置。

支持系统拖拽接口实际导出的格式：文本、图片、文件／目录、文件承诺及后续明确支持的 MIME／UTI。只存在于源应用内部、没有系统可导出格式的专有对象，不能保证跨应用或跨系统无损拖动；目标应用仍须支持相应格式。不得冒充全对象通用支持。 即使应用提供自定义MIME／UTI，若载荷只是源进程对象标识或本机资源引用，也需要该应用提供可移植导出；仅传递这些字节不等于目标可用。

## 当前代码事实

- 默认桌面产品是 GPUI → OriginalOwner → SessionState → WorkspaceConnection；不是 standalone client 的环境变量开关路径。
- 文本／图片已有可靠剪贴板通道，文件已有分块、完整性校验、分组收取及原生文件引用桥接。
- 本轮已在默认 viewer 接入文件引用桥接，并将有效剪贴板所有权绑定到最近聚焦且仍选中、可见、已连接的会话；延迟启动和旧会话读取按所有权代次失效。针对性检查通过，正在独立复核，尚未发布或完成真实跨机粘贴验收。
- GPUI 目前可以报告外部文件路径拖入，但产品没有处理器；没有来自远端原生拖放的内容 offer。完成文件复制粘贴不等于已完成远端应用之间的拖放。

## 实施顺序

1. **当前迭代：复制粘贴。** 将文件桥接接到已有连接的文件 commands/events。由用户偏好、连接状态、选中窗口及最近的远程窗口焦点决定唯一有效剪贴板目标；切到本地应用粘贴时保留该目标，聚焦另一远程窗口时再交接；改变焦点不能取消普通文件传输，旧会话完成事件不能覆盖新目标的剪贴板。覆盖文本、PNG/TIFF及文件引用，沿用原生平台适配器与回环抑制。Android按系统允许的前台访问范围实现，不绕过系统限制。
2. **本地文件拖入远程窗口。** 接入现有 GPUI FileDropEvent，明确绑定目标会话／来源。文件内容复用现有文件传输；区分“收到文件”和“目标应用已接受放置”。先验证接收流程，再接各平台原生 drop 适配。
3. **远程窗口 A → B 的原生拖放。** 来源端导出受当前控制会话约束的 offer（格式、允许操作、有限元数据、可延迟获取的内容句柄）。本地 viewer 保持拖拽视觉与目标命中即时响应；目标确认后按需取内容，复用现有可靠传输和完整性检查，最终由目标平台适配器完成原生放置。
4. **按需内容与格式扩展。** 文本／小图片直接发送；大文件、目录和承诺文件只在目标确定后获取。先保证副本与取消语义；跨机移动须在目标确认落地后才允许源端删除，不把传输开始视为移动成功。

## 共同约束

- 拖放 offer 和内容句柄绑定设备、会话、来源及有效期；不能让任意路径或旧窗口事件借用另一会话权限。
- 不在拖动每一帧传输文件，不缓存已失效的拖放会话，不用主界面轮询阻塞视频或输入。
- 几何映射沿用当前帧的裁剪、缩放、DPI和旋转；离开、取消、窗口关闭、连接中断都应清理按住状态与拖放会话。
- 目标不支持格式时给出明确拒绝，不偷偷改为其它操作。图像、文件名、Unicode、多个文件、目录、超大文件和中途取消分别验收。

## 验收与接续

先用独立测试内容验证 Mac ↔ Mac 的文本／图片／文件及两个 viewer 焦点切换，再覆盖 Windows、Linux 与手机受支持的系统操作。记录接收端独立内容 SHA、真实系统粘贴结果和原生目标应用的接受结果；源码、单测、传输成功和实际粘贴／drop 分别报告。

真实验收还需覆盖：复制后立即切到本地粘贴、X→Y→X重用、文件与文字／图片交替、旧大文件仍在传输时复制新内容、同一路径文件修改后再次复制，以及新连接建立时两端已有不同剪贴板的方向。当前针对性测试不能替代这些系统行为验收。

当前本文记录目标和分期，不代表跨远程窗口拖放已经实现。每次交付在设备验收记录中标出已实现的具体格式、系统和实际链路。

## 终态交互补充（2026-11-07）

用户期望：原系统中能拖动的对象，尽可能直接从远程窗口 A 拖入远程窗口 B，不要求先保存到本机、手动上传或切换到文件管理页。A、B 可以来自同一设备或不同设备；本地窗口与远程窗口也属于同一套交互。

- 文件管理器 → 文件管理器：保持文件名、内容和目录结构，遵守目标的重名处理；跨设备移动仅在目标完整接收且确认后删除来源。
- 文件管理器 → 聊天／邮件：目标应用收到原生文件拖入并生成附件；只完成传输不算通过。
- 浏览器／编辑器 → 另一应用：由目标从源端实际导出的文本、链接、图片等格式中选择；不能只传一张拖动对象的截图冒充对象。
- 拖动过程中立即显示拖动预览及可接受／不可接受、复制／移动状态。跨窗口时撤销旧目标，放下后才提交新目标；断线或取消不得误操作另一窗口。
- 共用剪贴板的格式转换与内容传输，但原生拖放使用独立的会话和生命周期，不通过改写用户剪贴板模拟拖放。

必须区分内容拖放与源应用内部操作：拖动窗口标题栏、滑块、选区手柄或没有可移植导出的私有对象，并不自动产生可跨设备携带的内容。对这些对象保留原应用操作；只有系统或应用真正提供可移植数据时才能扩展为跨机拖放。产品不会承诺无条件支持“所有可拖动对象”。
