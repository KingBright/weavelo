# 主动投送、画板与教学模式

2026-10-30，依据用户本次明确要求补充后续规划。目标是手机和电脑都能主动把画面或画板推给另一端，并在教学时使用特殊光标和画面批注。本文件记录待实现范围与完成条件，不表示这些功能已在全部真机上通过。

## 产品范围与优先级

覆盖 Mac Studio、MacBook、Windows cube、Linux HO5，以及分别接在两台 Mac 上的努比亚和红米手机。电脑→手机、手机→电脑必须双向实现；统一支持电脑→电脑和手机→手机。六台设备最终按 30 个有向设备对记录结果，不能以两个 Mac 的结果代表其他设备。

| 顺序 | 交付 | 用户可见的完成状态 |
| --- | --- | --- |
| P0，当前继续 | 完成现有文件、视频、控制、通知和音频互通，修复鼠标、键盘及 UU 套 Weavelo 的问题 | 每个方向有独立真机证据；当前权限受限项明确保留为待验收 |
| P1 | 补齐各端主动投送屏幕/可用应用窗口，以及接收、停止和恢复 | 从任一端选设备发起，对端直接进入明确标识来源的观看界面；不需要复制命令或改到对端手工拉取 |
| P2 | 本地画板和主动推送画板 | 手机或电脑创建画板后选择接收设备，另一端实际看到同步笔迹，退出和重连行为正确 |
| P3 | 教学模式：特殊光标、激光指示和画面叠加批注 | 讲解者可以在已投送画面上指示、画画，并随时切回远端操作；笔迹、光标与画面始终对齐 |

P1 先做一个电脑与一个手机的双向完整闭环，再在同一迭代中补齐其他平台差异并逐对验证。P2 的笔迹模型、渲染适配器和同步逻辑直接供 P3 使用。保持小步交付，不把画板、课堂管理或多人协作扩成另一个产品。

## 主动投送的交互

设备卡片提供“推送画面”和“推送画板”。推送画面时选择当前屏幕或平台真实支持的应用窗口，再选择已配对接收设备。观看与控制分开：推送画面不自动授予输入控制，也不自动开启麦克风或系统音频。

接收端显示发送设备、真实应用图标/名称、来源和当前共享状态。已明确接受该设备投送的会话直接打开；其他请求使用一次清楚的接收/拒绝交互，避免每次重复确认。推送不会抢走另一条会话的输入焦点。来源限制、离线、拒绝、忙碌、权限不足、对端已停止等状态必须可理解，不能显示“已推送”却只有空窗口。

电脑沿用原生观看窗口和紧凑工具条，提供本地全屏、恢复、最小化、停止。手机沿用原生全屏观看与触摸入口，明确区分直接触控、触控板、画笔和指示器。前台收到投送直接展示；后台按系统允许的通知与返回入口处理，不承诺绕过后台启动限制、锁屏或录屏授权。

发送方和接收方都能结束本次投送；结束只清理这条会话持有的媒体、笔迹和输入状态。断线后显示真实状态，恢复时验证原设备、来源和会话归属，取当前画面/画板状态，不能重放过期的点击和按键。原来正常的文件传输不因停止投屏而中断。

## 可主动推送的画板

第一版提供画笔、荧光笔、颜色/粗细、橡皮擦、撤销/重做和清空，支持鼠标、手指及平台实际提供的触笔。触笔压力可作为可选输入，不让无压感设备失去基础功能。移动端缩放/平移与绘画手势有明确区分，避免双指移动留下笔迹。

画板保存源画布的逻辑尺寸与矢量笔迹，不按接收端像素重写数据。第一版由发起方单写，接收方观看；以后确有共同书写需求再增加明确的书写权交接，不先引入多人冲突合并、角色系统或独立协作服务。

画板通过同一设备列表主动推送。可靠同步笔迹的开始、点批次、结束、擦除和撤销；重连采用当前快照与后续增量。点批次和历史均有界，持续绘画不能阻塞控制、音频或视频。光标移动可以合并旧位置，已确认的笔迹不能随意丢弃。完整文件导出、云端长期保存和课堂录制留在后续需求，当前不作为首版前置条件。

## 教学模式与批注

教学模式附着于当前投送会话。工具条有三个清晰模式：“操作”“画笔”“指示器”。操作模式走现有远端输入；画笔和指示器只生成教学事件，不向远端系统注入鼠标点击。模式切换先释放已按下的键和按钮，再开始新手势。

指示器使用易辨认的特殊光标，可切换激光点；按下或强调时有短暂、克制的视觉反馈。它是教学叠加层，不修改远端系统光标或安装系统驱动。批注支持画笔、荧光笔、橡皮擦、撤销和清空，与画板复用笔迹实现。

第一版支持随投送画面讲解，也支持接收方在本地临时标注；只有明确取得本次书写权时，接收方的标注才同步给其他观看者。批注绑定具体设备、来源及几何版本；切换来源默认结束旧笔划并清除旧的教学层，不能把上一应用的笔迹贴到下一应用。短时断线可恢复同一来源的已确认批注，但不恢复旧输入动作。

## 统一坐标与原生性能

画面、命中测试、远端输入、教学光标和笔迹共用同一几何模型。先取得源的有效内容矩形，再计算接收端布局中的显示矩形及缩放/平移/裁剪变换；输入使用这个变换的逆变换。编码填充、黑边、工具条和系统键盘区域不能成为远端内容坐标。

手机键盘弹出、横竖屏切换、分屏、窗口缩放、DPI 改变、源窗口移动或裁剪变化，都更新几何版本并取消旧手势，释放仍由旧会话持有的输入。笔迹存源逻辑坐标，渲染时再变换；不要把 macOS point、Windows DIP、Android dp 与视频像素混用。手写和触控板模式不共用含糊的事件解释。

共享 Rust 会话、目标绑定、几何、笔迹数据和事件校验；平台适配器负责原生捕获、编码/解码、呈现、触笔和系统输入。继续使用原生 GPU/视频资源，不为批注把整帧视频读回 CPU 或转成 RGBA，不把笔迹烘焙进每帧视频作为默认同步方式。

P2 开始时先验证各平台的叠加层如何进入采集：源端画出的笔迹可能已被屏幕采集包含，接收端再画一次会重影；双向投屏还可能形成画面回环。对每种实际采集后端明确采用一次合成路径，验证能否排除本地工具层。不能假定所有平台都能排除窗口；确实无法排除时，选择清楚的单次合成方案并记录其限制，再落具体平台代码。

指示器合并过期位置、笔迹按小批次发送，起止与所有权事件保持可靠有序；不让本地绘画等网络往返才显示。保留当前有界队列和视频参考帧规则，不为新功能重写第二套媒体管线。测量首次可见耗时、笔触本地/远端延迟、帧间隔、控制延迟、CPU/GPU、内存、带宽及手机功耗；对照同设备同分辨率的无批注基线记录中位数和 P95/P99，出现回退时直接定位与修复。

## 沿用现有实现与系统约束

定向投送从 `host/src/directed_delivery.rs` 的当前认证连接与有界投送意图、桌面 `Send screen` 入口继续；先核实现有闭环和缺口，再补手机发起与接收。Android 复用 `SessionConnectionService`、`WorkspaceClient` 和现有投屏服务的生命周期，不另建保活连接、设备身份或消息服务器。

画板/批注事件沿用已认证会话和来源归属，随自有设备统一升级当前协议；不引入旧协议兼容分支。产品入口与发布继续使用 Weavelo 域名，Octendra 只承担设备管理。现有控制指令和通知仍是本轮消息验收范围，不增加独立聊天模块。

Android 投屏、音频、无障碍控制以及 Linux portal 使用实际系统授权；没有授权时保留仍可工作的接收、文件和画板能力。后台观看与后台作为投屏源分开处理。当前 HO5 屏幕/控制授权、努比亚对外投屏/控制授权和红米安装身份验证仍待用户可操作时完成，不能视为功能已验收。

| 坐标与输入法 | 中心、四角、拖动跨区；fit/fill、缩放/平移、横竖屏、键盘开合、分屏、不同 DPI 均对齐；旋转/缩放中取消手势正确 |

只在 primary `main` 和现有单一 worktree 小步修改，相关检查通过后提交、推送并核对远端，使用已有正式打包、签名和兼容升级流程。有问题当场修复，不增加人工补丁哈希确认、功能分支、发布代际或额外回退副本。
