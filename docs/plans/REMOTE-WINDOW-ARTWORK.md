# 远控应用图标和设备角标

独立应用窗口保留应用原图，在右下角叠一枚设备角标。MacBook 用笔记本轮廓，Mac Studio 用主机轮廓，Windows 用四格窗，Linux 用企鹅。角标下沿加一行小字号设备名，底部名称用应用名。整屏会话以设备图标为主体。窗口标题显示应用名与设备名，Dock 菜单用应用名打开对应会话。

设备名称旁增加「设备角标」。默认按来源机器的系统和机型选择，也可以选择内置样式或导入自定义图片。导入沿用系统文件选择器，将 PNG、JPEG 或 WebP 归一为透明背景的 64 × 64 PNG，限制输入体积和解码尺寸。设置由本机保存，预览立即更新，接收方下次打开或切换来源时读取新标志。

来源选择器继续使用现有 64 × 64 缩略图。确认打开一个来源后，接收端通过同一个已认证的会话发起一次外观请求，携带当前来源和请求编号。来源端从该来源绑定的应用读取最多 256 × 256、256 KiB 的原生 PNG，并返回设备样式或最多 64 × 64、16 KiB 的自定义角标。仅查询当前有效来源，按内容哈希缓存；连接、来源或请求已变化时丢弃旧回包。屏幕和摄像头可以返回设备角标，应用原图字段为空。

新增外观请求与应答，沿用现有控制消息分片、会话鉴权、原生图标读取和发布流程。图标读取、解码与合成只在资产变化时运行，Dock 使用现有每会话辅助进程。显示路径保留原图的比例、颜色和透明边缘。默认标志预览覆盖 Dock 小尺寸和 Retina 尺寸。

验收使用 MacBook 和 Mac Studio 的实际 Dock。对比同一应用在两台机器上的图标，检查 Windows 和 Linux 来源的默认标志，保存一个自定义图标并重开会话确认同步。验证切换应用后图标正确更新，关窗后对应 Dock 项退出。保留源目录、输入、音视频和关闭行为。

## 已验证的交互

本地合成、预设和图片导入已通过检查。原生 Dock 绘制测试用 256 像素 ChatGPT 图标验证了 MacBook 与 Mac Studio 的设备标记。

两台 Mac 已安装各自原签名的 128。Studio 实际拉取 MacBook 的 ChatGPT 窗口时，Dock 项底部显示应用名，角标显示来源设备名。停止会话后对应 Dock 项退出。macOS 仍报告签名包的系统名称 Weavelo。当前串流使用现有来源缩略图和通用设备标记，高清应用原图、真实机型与自定义角标的跨设备读取由用户在“继续，把所有已知问题和剩余事项都做完……android 设备也要一起考虑”中授权继续。实机结果见[设备验收记录](../testing/2026-11-05-DEVICE-ACCEPTANCE.md)。

## 六端实现 · 2026-11-05

当前协议统一升为 8。外观请求绑定已建立的订阅、来源和请求编号；图标失败只影响外观，不结束视频。应用原图使用至多 256 像素，列表仍保留 64 像素缩略图。原生读取、解码与合成都在资产变化时进行；接收缓存复用相同内容。

Android 作为来源返回手机标志，设备名字继续使用真实型号。设置页显示型号、内置标志和自定义图片入口；作为接收端，将应用图标及设备角标用于当前串流的最近任务项，离开串流后恢复主入口图标。普通屏幕投送仍使用已有 MediaProjection 授权流程。
