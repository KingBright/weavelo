# 来源选择器：对齐、分组、搜索与预览

2026-11-05。用户已要求修正对齐、分组与名称筛选；这些普通界面修复直接实施。预览是待选择的新增行为，本稿不等同于它已实现或实机验收。

## 直接实施的列表改进

- 每行使用固定宽度的选择标记和图标列，名称始终左对齐。长标题省略，完整标题通过提示查看，不改变其它行的起始位置。
- 保留屏幕、应用窗口、摄像头三类。应用窗口按已有的应用名称分组，同组窗口缩进；组与窗口均按名称稳定排序，以来源标识作为同名项的最终排序条件。当前目录没有父进程或父窗口关系，不伪造进程树。
- 名称筛选同时匹配应用和窗口标题；桌面和 Android 含义一致。筛选隐藏条目不清除其已选状态，重新刷新则沿用现有来源归属、失效条目移除和最多八项规则。没有匹配项时提供清除筛选的入口。
- 继续沿用既有 GPUI / Compose、真实图标、主题和来源选择与确认流程。打开选择器不自动连接桌面。

## 预览方向比较

| 方案 | 行为 | 优点 | 代价 |
| --- | --- | --- | --- |
| **紧凑列表＋选中预览（推荐）** | 一次只预览当前聚焦、由用户选中的来源。桌面右侧小预览；窄屏改为列表上方。 | 搜索、长标题和应用分组清楚；最多一个额外编码订阅。 | 不能同时看见所有窗口的内容。 |
| 可见网格缩略图 | 仅为当前可见的最多四个格子开启预览，滚出后停止。名称仍可筛选与分组。 | 更容易按画面辨识窗口。 | 至少增加多路编码、传输和解码；窗口多时更多滚动，与其它会话争用硬件。 |

推荐第一种，保持默认管理窗口紧凑。桌面选择器宽度不超过现有管理窗口可用宽度，列表保留固定列；约 192 × 108 的展示区采用适应比例和黑边，编码最大 640 × 360、2 FPS、800 kbps。手机设备页保持原方向，选中预览不触发串流页横屏；键盘出现时优先让筛选框与列表可见。具体间距以实际 GPUI / Compose 渲染复核，示意尺寸不是实机完成证据。

## 预览的具体实现边界（等待用户选择）

1. 复用现有鉴权、原生采集／硬件编码和视频订阅，不新增截图轮询、JPEG 通道、目录图片协议或全窗口常驻预览。关闭选择器、取消、切换来源或失去授权立即释放该选择器持有的订阅。
2. 首次打开不预览默认桌面；用户聚焦某个来源后才请求。短暂合并快速切换，只保留最新选中目标。预览只显示画面，不开启远控输入或音频。
3. 预览沿用当前订阅容量，不抢占已有串流；硬件编码不足或系统尚未授权时显示简短原因，选择和正式打开仍可继续。平台没有提供的屏幕／应用不通过预览绕过系统授权。
4. 预览返回帧必须与当前设备、会话、来源及几何相符。旧来源晚到的帧不显示到新来源；缩略图不进入发现广播，不写入用户文件，不缓存私人画面到磁盘。
5. 正式确认仍使用现有打开／替换／投送逻辑，先结束预览，再建立对应的正式会话。不能用预览首帧证明正式会话已呈现。
6. 验证名称长短、重复应用、同名窗口、刷新中与无结果、筛选后的多选、快速切换、容量不足、断网、关闭与重新打开。新增预览另验真实首帧、旧帧隔离与硬件资源释放；各平台实际渲染和测试结果分别记录。

仓库 AGENTS.md 要求重大 GUI／原生媒体变更先确认具体方案。因此普通列表修复继续进行，新增原生预览按本稿取得一次选择后再实施，不新增日常构建或升级确认。
